# Odin → Go / React migration

## Preserved behavior

The corrected Odin version is the behavioral reference. Its source and tests were used to verify the Go port, then removed along with their archive copies and obsolete run/build scripts. The README, design brief, extracted source comments, artwork and tools remain in docs/legacy. Old documentation describes the historical build; current entry points are backend and frontend. No Odin compiler or source files are required.

## Corrections retained

- Scalable household/person storage and no lifetime birth quota from dead records.
- Correct age-dependent nutrition, fuel and work capacity.
- Biological father captured at conception; inherited constitution and ancestry rules.
- Configured year/pregnancy lengths, newborn age zero, correct death statistics.
- Individual spear condition retained through buying, selling, breaking and equipping.
- Mutually beneficial barter, checked real inventories, no artificial trade bonus.
- Exact zero regeneration and correct live ring-window barter medians.
- CSV precision and complete history beyond the metric ring.
- Deterministic hashes based on decision-relevant state.

## Verification evidence

- Odin fixture: seed 98765, 10 households, 1000 days. A complete Odin JSON world is stored as internal/sim/testdata/odin-seed-98765-day-1000.json.gz. TestOdinParity runs the Go simulation and compares every semantic field through the same Go hash after decoding the fixture. It covers RNG, people, households, ancestry, tools, resources, schedules, metrics and event/exchange rings.
- A separate seed 12345, 40-household, 5000-day run produced a CSV byte-for-byte equal to corrected Odin after normalizing line endings.
- The independent fixture was generated by running the corrected Odin simulation with its default configuration, 10 households, seed 98765 and trade enabled for 1000 days, then serializing the complete world as JSON and compressing it with gzip. Its generator was removed with the Odin source. Keep this fixture immutable; never regenerate it from Go. Its SHA-256 is `a82751e372cbe8eacd7123dbe17d9c6c1615ccb11cfd456f9e3e984ffe52141d`.
- Go tests cover simulation regressions, SQLite reopen/resume, atomic failed writes, stale revisions, checksum validation, complete archives, concurrent/idempotent commands, playback timing, observer input during play, WebSocket exchange and origin rejection.
- Experiment tests compare serial execution with four concurrent workers.
- Race detector checks run against the Go packages.
- TypeScript is checked on every production build. The app is additionally exercised in a real browser.

Go's hash encoding differs from the old Odin numeric hash; the numeric digest is not promised to match across languages. World state and economic output are compared directly using one encoding. Integer quantities and deterministic update order are unchanged. Supported application builds target 64-bit platforms.

## Added infrastructure

SQLite now persists everything required to resume play, every completed day's observations, all exchanges, accepted commands, runtime controls, camera/selection and experiment results. New/reset worlds preserve previous worlds. The browser reconnects and safely retries commands with uncertain outcomes.

The simulation's bounded rings still govern its economic memory and ratio calculations, preserving existing behavior. Full database archives add observation history without changing what agents know.

The UI is completely replaced. Pixi draws the game world; React/Tailwind owns the interface. Cosmetic family names, terrain placement offsets and animation never change the simulation. The original three terrain classes and five goods remain; the supplied visual reference does not introduce a fishing or weather system.

## Scope of concurrency

Independent seeded experiments are parallel. Socket IO, simulation ownership and database work have separate goroutines and bounded queues. Resource competition and RNG-consuming decisions remain ordered to preserve parity.

## Remaining model limits

This remains the same economic model: no farming, currency, banking, wage employment, disease, war or policy system. Families have simplified residence and reproduction rules. Abandoned huts remain; camp slots have a finite limit. Direct observed barter ratios can be unavailable. High requested playback speeds are limited by CPU, persistence and rendering throughput.
